# День 22 — два режима RAG и сравнение качества

## Контрольный набор

Десять вопросов, ожидания и нужные разделы PDF находятся в
[`evaluation/day22-questions.json`](../evaluation/day22-questions.json). Номера страниц —
номера страниц PDF, а не печатные страницы книги. Вопросы 1–9 требуют
подтверждения из книги. Вопрос 10 проверяет, что модель не приписывает
нерелевантному фрагменту сведения о Kotlin coroutines.

## Как повторить сравнение

1. Установить зависимости из `requirements-dev.txt` и `requirements-indexing.txt`.
2. Положить официальный sample PDF в `data/documents/jcip-sample.pdf` и загрузить `.env`.
3. Выполнить `python -m evaluation.run_day22 --output data/day22-evaluation.json`.
4. Проверить для каждого вопроса два ответа, `search_query`, `top_hits` и `sources`.
5. После обновления ручной оценки в `evaluation/day22-review.json` выполнить
   `python -m evaluation.make_day22_video`: получится 36-секундное видео без
   звука в `artifacts/day22-rag-comparison.mp4`.

Прогон вызывает тот же `ChatSessionService.send`, что и HTTP API. Каждый ответ
получает новую пустую сессию. Профиль, память и общие правила форматирования
отключены в обоих режимах. Результат сохраняет модель, версию индекса и SHA-256
PDF, чтобы сравнение можно было воспроизвести. Скрипт автоматически отмечает
попадание ожидаемого раздела и страницы в top-3, но не объявляет фактическую
правильность ответа.

## Рубрика ручной проверки

Для каждого ответа отдельно отметить:

- **Факты:** `1`, если все ключевые пункты из `expected` присутствуют и нет
  существенной ошибки; иначе `0` с короткой причиной.
- **Источники:** для RAG ответов 1–9 отметить `1`, если процитированная страница
  действительно поддерживает утверждения; иначе `0`. Отдельно записать
  `expected_source_in_top_3`, чтобы отличить ошибку поиска от ошибки генерации.
- **Вопрос 10:** ответ должен сообщить, что найденные фрагменты не подтверждают
  тему, и не иметь ссылок на книгу. Отсутствие темы во всём PDF нельзя выводить
  только из top-3 результатов. Ответ без RAG не должен утверждать, будто
  проверил индекс.

Сравнивать число фактически полных ответов из 10 для обоих режимов. Для RAG
дополнительно сообщить число корректно подтверждённых ответов из девяти
вопросов по книге, число попаданий нужного источника в top-3 и число ложных
ссылок. Фактическая полнота и качество цитирования — разные показатели.

## Сценарий видео

1. Показать локальный PDF и статус индекса, затем переключатель «Без RAG / С RAG».
2. В двух новых чатах задать вопрос №5: сопоставить ответы, метку режима и
   страницу источника; обновить чат, чтобы показать сохранение режима и ссылки.
3. Показать вопрос №9 и найденные чанки: он проверяет подготовку поискового
   запроса для русской формулировки.
4. Показать вопрос №10: у ответа не должно быть ложной ссылки на PDF.
5. Открыть JSON прогона и итоговую таблицу ручной проверки, назвать обе оценки
   и один конкретный пример улучшения либо ошибки RAG.

Не использовать два последовательных ответа в одном чате как контрольную пару:
второй запрос увидит первый ответ в истории. Для видео выбирать новые чаты.
